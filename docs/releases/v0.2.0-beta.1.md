**Beta for field testing — first build meant to be taken to a car.** It replaces v0.1.0-rc.1, which was never used on a real vehicle. Everything works against the built-in simulators and is checked against the original IES2 code, but no ECU has been read with it yet: expect problems with timing, detection or single parameters, and please report them with a line trace attached.

## What's in it

IAW units (FIAT, Lancia, Alfa Romeo, OBD-I, 3-pin connector):

- Desktop application (Avalonia) for Windows, Linux (also Raspberry Pi) and macOS, interface in English and Italian
- Automatic ECU detection with ISO and CODRIC codes, vehicle model and immobiliser; ECU search by label code (e.g. IAW 4WF.P8), car or brand
- Dashboard grouped by system, vehicle card, live parameters table with the real refresh rate
- Engine and immobiliser errors, clear codes; actuator tests and adjustments, each behind a confirmation
- Interactive graphs, CSV recording, replay of recorded logs (also IES2 exports)
- `iaw-cli` command line tool, read only unless `--allow-active` is given
- ECU definitions as JSON for IAW-6F/16F, 8F/18F, 8F.68, 18FD/1G7 and Weber-Marelli 04K.P8

New in this beta:

- **Line trace**: every byte on the K-Line saved to a text file (`--trace file.txt`, or Options → "Save a line trace"); `iaw-cli trace file.txt` summarises it. Attach one to every report.
- **Trace replay**: `iaw-cli read --replay file.txt` answers with a recorded session, in place of the car
- **Automatic reconnection** after a communication loss, with the likely cause: no echo from the adapter, wrong echo, or no answer from the ECU
- **Network bridge** (RFC 2217): `iaw-cli bridge` shares the cable on the network, e.g. from a Raspberry Pi left in the car; connect with `--port rfc2217://host:2217` or Options → "Network bridge"
- **OBD-II / EOBD** for the cars of 2001 and later, same cable, command line only: `iaw-cli obd identify|read|dtc|clear` (ISO 9141-2 and KWP2000, standard live data, trouble codes, VIN)
- **NuGet packages** of the libraries (Core, transports, simulator), attached to this release

## Downloads

Self-contained executables, no .NET install needed. Each archive holds the desktop application (`marelli-iaw-ecu-studio`) and the command line tool (`iaw-cli`). Checksums are in `SHA256SUMS.txt`. The `.nupkg` files are the libraries, for developers only.

| System | File |
| --- | --- |
| Windows x64 | `…-win-x64.zip` |
| Linux x64 | `…-linux-x64.tar.gz` |
| Raspberry Pi / Linux arm64 | `…-linux-arm64.tar.gz` |
| macOS Apple silicon | `…-osx-arm64.tar.gz` |

The executables are not signed: Windows SmartScreen and macOS Gatekeeper will warn the first time (on macOS: right-click → Open, or `xattr -d com.apple.quarantine`).

## Field test checklist

Hardware: VAG-COM KKL 409.1 cable with a genuine FTDI chip and an OBD2 → FIAT 3-pin adapter, see [docs/hardware.md](../hardware.md). Set the FTDI latency timer to 1 ms. **Always add `--trace` (or tick "Save a line trace")**, start with read-only operations, and keep the engine off unless a step says otherwise.

IAW car (1990s, 3-pin connector):

1. `iaw-cli ports` finds the cable (and warns if the latency is 16 ms)
2. `iaw-cli identify --port … --trace identify.txt`, then turn the ignition on: ISO code, ECU and vehicle are detected. Repeat with `--no-broadcast` and the ignition already on
3. `iaw-cli read --port … --count 0 --csv idle.csv --trace idle.txt` with the engine at idle: values are plausible (rpm, coolant temperature, battery voltage, MAP, lambda) and the refresh rate is stable
4. While reading, unplug and replug the 3-pin connector, or turn the ignition off and on: the loss is reported with its cause and the reading resumes by itself
5. Same in the desktop application: dashboard, parameters table, graphs, recording and replay
6. `iaw-cli errors --port …`: errors match a known state (for example a disconnected sensor)
7. Only afterwards, and with care: clear codes and one actuator test

Optional:

8. Network bridge: `iaw-cli bridge --port /dev/ttyUSB0 --listen 0.0.0.0:2217` on a Raspberry Pi, then steps 2-3 from another computer with `--port rfc2217://<pi>:2217`
9. OBD-II car (2001 or later, 16-pin connector, no 3-pin adapter): `iaw-cli obd identify --port … --trace obd.txt`, then `obd read` and `obd dtc`

For each test please note car, engine, ECU label code, cable, operating system and the result, and attach the line trace (and the CSV log if a value looks wrong).

## Known limits

- Never tested on a real car: the built-in definitions are ported from IES2 and marked `verified`, so actuator tests, clear codes and adjustments are available behind a confirmation; leave them for last
- OBD-II is in the command line tool only, and covers the standard data, not the manufacturer data of each ECU; CAN cars (about 2008 on) are not supported
- ser2net and esp-link should work as network bridges but have not been tried; J2534 adapters are not supported
- The compatible-vehicle lists on the vehicle card are indicative
- macOS build only for Apple silicon

## Italiano

**Beta per le prove sul campo: la prima versione pensata per essere portata in macchina.** Sostituisce la v0.1.0-rc.1, mai usata su un'auto vera. Tutto funziona con i simulatori integrati ed è verificato con il codice originale di IES2, ma nessuna centralina è ancora stata letta: possibili problemi di tempi, riconoscimento o singoli parametri. Segnalateli allegando un trace della linea.

Novità di questa beta: trace della linea (`--trace file.txt`, oppure Opzioni → "Salva il trace della linea") e riproduzione dei trace; riconnessione automatica con la causa della perdita di comunicazione; bridge di rete RFC 2217 (`iaw-cli bridge`, per esempio da un Raspberry Pi in auto); modalità OBD-II per le auto dal 2001, solo da riga di comando (`iaw-cli obd`); librerie come pacchetti NuGet.

Gli archivi contengono l'applicazione desktop e lo strumento a riga di comando `iaw-cli`, già pronti senza installare .NET. Seguite la checklist qui sopra: **aggiungete sempre `--trace`**, partite dalle sole letture (porte, identificazione, parametri al minimo, prova di stacco del connettore, errori), e lasciate cancellazione errori e test attuatori per ultimi. Per ogni prova annotate auto, motore, codice sull'etichetta della centralina, cavo, sistema operativo ed esito, allegando il trace della linea e, se un valore non torna, il log CSV.
