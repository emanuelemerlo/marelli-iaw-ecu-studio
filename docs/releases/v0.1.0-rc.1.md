**Release candidate for field testing — not yet tested on a real car.**

This is the first build of marelli-iaw-ecu-studio meant to be taken to a car. Everything has been checked against the built-in simulator and the original IES2 code, but no ECU has been read with it yet. Expect problems with timing, detection or individual parameters, and please report them.

## What's in it

- Desktop application (Avalonia) for Windows, Linux (also Raspberry Pi) and macOS, interface in English and Italian
- Automatic ECU detection with ISO and CODRIC codes, vehicle model and immobiliser
- ECU search by label code (for example IAW 4WF.P8), by car or by brand
- Dashboard grouped by system, vehicle card, live parameters table with the real refresh rate
- Engine and immobiliser errors, clear codes
- Actuator tests and adjustments, each behind a confirmation
- Interactive graphs, CSV recording, replay of recorded logs (also IES2 exports)
- `iaw-cli` command line tool, read only unless `--allow-active` is given
- Built-in simulator
- ECU definitions as JSON for IAW-6F/16F, 8F/18F, 8F.68, 18FD/1G7 and Weber-Marelli 04K.P8

## Downloads

Self-contained executables, no .NET install needed. Each archive holds the desktop application (`marelli-iaw-ecu-studio`) and the command line tool (`iaw-cli`). Checksums are in `SHA256SUMS.txt`.

| System | File |

The executables are not signed: Windows SmartScreen and macOS Gatekeeper will warn the first time (on macOS: right-click → Open, or `xattr -d com.apple.quarantine`).

## Field test checklist

Hardware: VAG-COM KKL 409.1 cable with a genuine FTDI chip and an OBD2 → FIAT 3-pin adapter, see [docs/hardware.md](../hardware.md). Start with read-only operations.

1. `iaw-cli ports` finds the cable
2. `iaw-cli identify --port …`, then turn the ignition on: ISO code, ECU and vehicle are detected (try both with and without the key-on ISO wait)
3. `iaw-cli read --port … --count 0 --csv test.csv` with the engine at idle: values are plausible (rpm, coolant temperature, battery voltage, MAP, lambda) and the refresh rate is stable
4. Same in the desktop application: dashboard, parameters table, graphs, recording, and replay of the recording
5. `iaw-cli errors --port …`: errors match a known state (for example, a disconnected sensor)
6. Only afterwards, and with care, clear codes and one actuator test

For each test please note car, engine, ECU label code, operating system and the result, and attach CSV logs if something looks wrong. If communication fails, attach a line trace too (`--trace file.txt`, or Options → "Save a line trace" in the application; see [docs/hardware.md](../hardware.md#reporting-a-problem-the-line-trace)).

## Known limits

- The built-in definitions are ported from IES2 and marked `verified`, so actuator tests, clear codes and adjustments are available (behind a confirmation): they have never been run on a car with this software, leave them for last
- The compatible-vehicle lists on the vehicle card are indicative
- macOS build only for Apple silicon

## Italiano

**Release candidate per le prove sul campo — non ancora provata su un'auto vera.**

Prima versione pensata per essere portata in macchina. Tutto è stato verificato con il simulatore integrato e con il codice originale di IES2, ma nessuna centralina è ancora stata letta. Possibili problemi di tempi, riconoscimento o singoli parametri: segnalateli.

Gli archivi contengono l'applicazione desktop e lo strumento a riga di comando `iaw-cli`, già pronti senza installare .NET. Seguite la checklist qui sopra partendo dalle sole letture (porte, identificazione, parametri al minimo, errori); cancellazione errori e test attuatori solo alla fine e con attenzione. Per ogni prova annotate auto, motore, codice sull'etichetta della centralina, sistema operativo ed esito, allegando i log CSV se qualcosa non torna.
