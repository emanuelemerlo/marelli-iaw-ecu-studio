**Beta for field testing: still not tried on a real car.** It replaces v0.2.0-beta.2, whose interface did not fit small screens and whose theme choice was hard to find. Compared with v0.2.0-beta.1 it brings a reworked interface with a dark theme, translations reviewed in every language, and a more robust K-Line init. Everything works against the built-in simulators and is checked against the original IES2 code, but no ECU has been read with it yet. Please report problems with a line trace attached. The new [real car report](https://github.com/emanuelemerlo/marelli-iaw-ecu-studio/issues/new?template=car_report.yml) form is the quickest way, and it is welcome even when everything works.

## What's new

### Interface

- **Opens maximised** the first time, then as you left it. A saved size that does not fit the screen (another computer, a smaller monitor) falls back to maximised. In beta.2 the window always opened at 1180×780, taller than a 768-pixel screen.
- **Fits the screen**: the dashboard and the parameter table grow or shrink to fill the window without scrolling.
  - They shrink down to a size that stays readable (0.8×), and scroll only below that.
  - On a full HD screen the instruments grow to about 1.4×.
- **Parameters on several columns** on a wide window, each group with its own column headers.
- **Dark theme**: follows the operating system by default (checked on Windows, macOS and Linux). The theme menu next to Options shows the current choice and offers system, light and dark; the choice is also at the top of Options, and it is saved. Instruments and graphs follow the theme too.
  - If the theme does not follow your system, run `marelli-iaw-ecu-studio --report-theme theme.txt` and attach `theme.txt` to a report: it says which theme the system reports and which one the window uses.
- **Alignment**:
  - toolbar controls all share one height;
  - the ECU box shows a single line;
  - the connected-ECU bar fits on one line, and the update rate moved to the status bar;
  - table headers line up with their columns;
  - dashboard status lights no longer cut their names.
- Fixed: the legend of a graph was repeated each time the graph was rebuilt.

### Translations

- Parameter, error and message names reviewed in all ten languages. Some were wrong in meaning, and a few of those were safety messages:
  - **German**: "ignition ON, engine STOPPED" said to switch both off, and "lambda in closed loop" read as "lambda control disabled".
  - **Croatian and Serbian**: engine speed was shown as vehicle speed. Serbian is now its own translation instead of a copy of Croatian.
  - **Italian**: typos such as "ignezione", idle shown as "inactivity", and English words (stepper, offset, duty cycle...) replaced with Italian terms; engine speed in giri/min.
- Strings left in English, typos and missing entries fixed in every language, including the English names inherited from IES2.
- Language names written as menu entries ("Italiano", "Español"); Serbian in Latin script, like its translation.
- A test now fails if a translation loses an entry or a placeholder, or leaves text in English.

### K-Line and OBD-II

- **The init is repeated when the computer was late.** The 5-baud address and the fast-init pulse are timed by the computer. If the operating system pauses the program at the wrong moment, the ECU reads a wrong address or ignores the wake-up.
  - The program notices a line change that came late, and then repeats the init, up to three attempts.
  - An init that fails with correct timing is not repeated, so an absent ECU or a wrong protocol is reported as before.
  - Each repeat appears in the line trace as "init repeated".
  - This was found on a busy macOS build machine, and it matters just as much on a slow laptop in the car.

## Downloads

Self-contained executables, no .NET install needed. Each archive holds the desktop application (`marelli-iaw-ecu-studio`) and the command line tool (`iaw-cli`). Checksums are in `SHA256SUMS.txt`. The `.nupkg` files are the libraries, for developers only.

| System | File |
| --- | --- |
| Windows x64 | `…-win-x64.zip` |
| Linux x64 | `…-linux-x64.tar.gz` |
| Raspberry Pi / Linux arm64 | `…-linux-arm64.tar.gz` |
| macOS Apple silicon | `…-osx-arm64.tar.gz` |

The executables are not signed, so Windows SmartScreen and macOS Gatekeeper warn the first time. On macOS, right-click → Open, or run `xattr -d com.apple.quarantine`.

## Field test checklist

Hardware: a VAG-COM KKL 409.1 cable with a genuine FTDI chip and an OBD2 → FIAT 3-pin adapter, see [docs/hardware.md](https://github.com/emanuelemerlo/marelli-iaw-ecu-studio/blob/main/docs/hardware.md). Set the FTDI latency timer to 1 ms.

**Always add `--trace`, or tick "Save a line trace" in the application.** Start with read-only operations, and keep the engine off unless a step says otherwise.

IAW car (1990s, 3-pin connector):

1. `iaw-cli ports` finds the cable, and warns if the latency is 16 ms.
2. Run `iaw-cli identify --port … --trace identify.txt`, then turn the ignition on: the ISO code, ECU and vehicle are detected. Repeat with `--no-broadcast` and the ignition already on.
3. Run `iaw-cli read --port … --count 0 --csv idle.csv --trace idle.txt` with the engine at idle. The values should be plausible (rpm, coolant temperature, battery voltage, MAP, lambda) and the refresh rate stable.
4. While reading, unplug and replug the 3-pin connector, or turn the ignition off and on. The loss is reported with its cause, and the reading resumes by itself.
5. Do the same in the desktop application: dashboard, parameters table, graphs, recording and replay.
   - New: check that the dashboard fits your screen and stays readable.
   - New: try the dark theme, ideally in the car at dusk.
6. Run `iaw-cli errors --port …`: the errors should match a known state, for example a disconnected sensor.
7. Only afterwards, and with care: clear codes and run one actuator test.

Optional:

8. Network bridge: run `iaw-cli bridge --port /dev/ttyUSB0 --listen 0.0.0.0:2217` on a Raspberry Pi, then repeat steps 2-3 from another computer with `--port rfc2217://<pi>:2217`.
9. OBD-II car (2001 or later, 16-pin connector, no 3-pin adapter): run `iaw-cli obd identify --port … --trace obd.txt`, then `obd read` and `obd dtc`. If the trace shows "init repeated", please mention it in the report.

For each test, open a [real car report](https://github.com/emanuelemerlo/marelli-iaw-ecu-studio/issues/new?template=car_report.yml), or note the car, engine, ECU label code, cable, operating system and result. Attach the line trace, plus the CSV log if a value looks wrong.

## Known limits

- **Never tested on a real car.** The built-in definitions are ported from IES2 and marked `verified`, so actuator tests, clear codes and adjustments are available behind a confirmation. Leave them for last.
- **Interface languages**: the interface itself (menus, buttons, options) is in English and Italian only. In the other eight languages only the parameter, error and message names are translated.
- **Translations to review**: Hungarian, Croatian and Serbian were rewritten without a native speaker; corrections are welcome.
- **OBD-II** is in the command line tool only, and covers the standard data, not each ECU's manufacturer data. CAN cars (about 2008 on) are not supported.
- **Network bridges**: ser2net and esp-link should work but have not been tried. J2534 adapters are not supported.
- **Compatible vehicles**: the lists on the vehicle card are indicative.
- **macOS**: the build is for Apple silicon only.

## Italiano

**Beta per le prove sul campo: ancora mai provata su un'auto vera.** Sostituisce la v0.2.0-beta.2, che non stava negli schermi piccoli e in cui la scelta del tema era difficile da trovare. Rispetto alla v0.2.0-beta.1 porta un'interfaccia rivista con il tema scuro, le traduzioni ricontrollate in tutte le lingue e un init della linea K più robusto. Tutto funziona con i simulatori integrati ed è verificato con il codice originale di IES2, ma nessuna centralina è ancora stata letta. Segnalate i problemi allegando un trace della linea. Il nuovo modulo [real car report](https://github.com/emanuelemerlo/marelli-iaw-ecu-studio/issues/new?template=car_report.yml) è il modo più rapido, e va bene anche quando funziona tutto (anche in italiano).

### Novità

- **Si apre massimizzata** la prima volta, poi come l'avete lasciata.
- **Interfaccia che sta nello schermo**: cruscotto e tabella dei parametri si ingrandiscono o si riducono per riempire la finestra senza scroll. Su uno schermo largo i parametri si dispongono su più colonne.
- **Tema scuro**: di default segue quello del sistema (verificato su Windows, macOS e Linux). Il menu del tema accanto a Opzioni mostra la scelta attuale e offre sistema, chiaro e scuro; la scelta è anche in cima alle Opzioni e viene salvata. Se il tema non segue il sistema, lanciate `marelli-iaw-ecu-studio --report-theme tema.txt` e allegate il file a una segnalazione.
- **Allineamenti**:
  - barra dei comandi a altezza uniforme;
  - dati della centralina su una riga;
  - intestazioni delle tabelle allineate;
  - nomi delle spie non più troncati.
- **Traduzioni ricontrollate in tutte e dieci le lingue.** Alcuni errori cambiavano il significato:
  - in tedesco "quadro acceso, motore spento" diceva di spegnere entrambi;
  - in croato e serbo il regime motore era la velocità del veicolo;
  - in italiano c'era "ignezione", e le parole inglesi (stepper, offset, duty cycle...) sono state sostituite da termini italiani; il regime è in giri/min.
- **Init della linea K ripetuto quando il computer è in ritardo**: se il sistema operativo sospende il programma durante l'init e la centralina non risponde, l'init viene ripetuto fino a tre volte. Nel trace compare "init repeated".
- **Progetto**: guida per contribuire, codice di condotta, politica di sicurezza e moduli per le segnalazioni.

### Prove sul campo

Seguite la checklist qui sopra.
- **Aggiungete sempre `--trace`.**
- Partite dalle sole letture: porte, identificazione, parametri al minimo, prova di stacco del connettore, errori.
- Lasciate per ultimi la cancellazione degli errori e i test attuatori.
- Novità da provare: che il cruscotto stia nel vostro schermo e resti leggibile, e il tema scuro in auto.

Per ogni prova aprite un real car report, oppure annotate auto, motore, codice sull'etichetta della centralina, cavo, sistema operativo ed esito. Allegate il trace della linea e, se un valore non torna, il log CSV.

### Limiti noti

- Mai provata su un'auto vera.
- L'interfaccia è solo in italiano e inglese; nelle altre otto lingue sono tradotti solo i nomi di parametri, errori e messaggi.
- Ungherese, croato e serbo vanno riletti da madrelingua.
- L'OBD-II è solo da riga di comando e senza auto CAN.
- La versione per macOS è solo per Apple silicon.
